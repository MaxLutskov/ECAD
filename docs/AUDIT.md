# Технічний аудит ECAD

Дата: 2026-09-10. База: `128401a` (application 0.17). Це знімок стану, не roadmap; черговість робіт визначає тільки [PLAN](../PLAN.md). Перевірено solution, усі області Core/Desktop, консольні checks, скрипти, приклади, документацію та Git. Аудит коду не є доказом відсутності інших дефектів. Надані раніше PDF повторно не перевірялися.

Документацію узгоджено 2026-09-11. Зміни цього аудиту обмежені Markdown: assemblies, runtime behavior, приклади даних і schema не змінено. Діагностичний harness залишений у ignored `tmp/audit`, не входить до продукту. Перенесення класів відкладено до 0.18, щоб спочатку зафіксувати інваріанти regression tests.

## Фактичний стан

Підсумок стабілізації 0.18: A01/A02/A05/A06/A07/A09/A12 виправлено; A03 — явні FunctionId зберігаються для ERC, Paste створює функцію явно; A04 — split/merge узгоджені, призначення редагуються окремо. A08 — ownership виправлено, PinId залишається 0.20. A10 — приватні snapshots і ContentRevision впроваджено; read-only UI models та події залишаються 0.19. A11 — рухомі анотації номерів залишаються 0.20. Докази й точні межі — [приймання 0.18](RELEASE-0.18.md). Матриця нижче зберігає початковий стан 0.17, а не поточний список відкритих дефектів.

## Виявлені дефекти та ризики

Прогрес другої частини 0.18: A05 виправлено (всі сторінки та ProjectDevice); A08 частково виправлено для ownership функції та посилань фізичного виконання. Нові regressions перевіряють також відмову без зміни стану, Undo/Redo і save/open. A03 (повторне використання вже наявної функції), split/merge та PinId залишаються відкритими. Історичні відтворення нижче стосуються baseline.

Пріоритет P1 — цілісність даних/ключовий робочий сценарій; P2 — функціональна неповнота/підтримуваність. Записи «за кодом» не видаються за відтворений UI-баг.

| --- | --- | --- | --- |

## Архітектура і перевірки

Восьмий крок: A12 закрито для UI/log/package version sources. Є workflow Windows/Ubuntu і спільний локальний verification script; лише локальний Windows результат підтверджено (119 checks + package check). За новою вимогою користувача невстановлена сумісність зі старими schema більше не блокує поточний етап; розширення міграцій відкладено.

Сьомий крок: матриця історичних writer тепер охоплює schema 6–11 (fixtures з відповідних Git commits, не просто зміна SchemaVersion у поточному DTO). Міграції, збереження геометрії/посилань, round-trip та незмінність джерела проходять. Усього 119 checks. Відсутність writer 1–5 задокументована; це залишає межу підтвердженої сумісності, попри прийняття loader версій 1–12.

Шостий крок: A09 посилено structural guard перед міграціями/нормалізацією; відсутні колекції, null entries, повторні ID/JSON-поля й неконсистентний active page відхиляються. JSON parsing має читабельну діагностику; library input обмежений 32 MiB. 113 checks включають незмінність session/history після відмови та захист попереднього файла при save. Це не твердження про повне fuzz-покриття чи міграції кожної історичної schema.

П’ятий крок: A07/A10 частково — SwitchPage не викликає Normalize; ContentRevision у snapshots відділяє навігацію від змін; no-op commit не забирає redo; dirty marker використовує savedRevision. 110 checks. Root/Pages дублювання та mutable arrays не усунено, JSON structural comparison є тимчасовим рішенням до domain equality/performance перевірки.

Четвертий крок: для зняття та зміни призначень тепер є UI і session commands. Обмеження split призначеного кола залишається навмисним, але користувач може пройти явний цикл clear → split → reassign. 108 checks. Повний редактор параметрів/кінців/екранів кабелю не реалізований цим кроком.

Третій крок стабілізації: явно заданий повторний FunctionId більше не замінюється при Normalize; ERC бачить дубль (A03). Команда Paste явно запитує нову функцію через відсутній FunctionId. Для A04 додано `NetReconciliation`: метадані зберігаються при split/compatible merge; при merge посилання клем/жил перепризначаються, поглинуті записи кіл видаляються. Конфлікти параметрів або locked numbers відхиляються атомарно. Split призначеного кола поки блокується. 106 checks, включно undo/redo, no-mutation-on-error та round-trip після merge. A04 закрито частково: orphan cleanup і UI reassignment залишаються.

Core не залежить від Avalonia, але об'єднує domain, application orchestration, persistence, приклади. Desktop напряму змінює domain records. `DrawingCanvas`, `MainWindow`, `PropertyPanel`, консольний `Program` перевірок концентрують багато відповідальностей. Статичні SymbolLibrary/WorkspaceFolders/AppLog ускладнюють ізоляцію. Service locator або Avalonia rendering у Core не виявлено. Детальні Problem → Impact → Target → Migration наведені в [ARCHITECTURE](ARCHITECTURE.md).

94 checks — один console runner, не 94 тести стандартного test discovery. Є geometry/domain, serialization/migration, session integration, headless UI, regression сценарії; вони змішані, runner зупиняється на першій помилці. Є migration test для v5, але немає матриці fixtures для кожної schema 1–11. Частина UI перевірок використовує reflection; render-without-exception не підтверджує якість верстки. Немає CI, stress/performance baseline, автоматичного контролю всіх електричних інваріантів чи реального Linux UI прогону. TODO/FIXME у src/tests не знайдено; це не означає відсутності боргу.

## Перевірено 2026-09-10

- `dotnet build ECAD.slnx --no-restore`: успіх, 0 warnings, 0 errors. SDK `10.0.400-preview.0.26322.102` вивів інформаційне NETSDK1057 про preview.
- `dotnet run --project tests/ECAD.Checks --no-build`: 94 checks passed; previews у `tmp/checks`.
- Локальний діагностичний harness у `tmp/audit` (ignored) відтворив A01/A02. Це спостереження дефектів, не додані passing regression tests.
- `ExampleElectricalProject.Create()` до і після Session.Load: ERC = 6 UnconnectedPin + 3 DanglingWireEnd + 5 MissingDeviceModel. Перевірка прикладу у checks перевіряє моделі/round-trip, не ERC=0. Назва `complete-electrical-demo` історична, не гарантія повноти.
- Реальний запуск GUI/довга ручна сесія, Ubuntu, друк, installer, продуктивність великих схем і електротехнічна відповідність стандартам цим аудитом не перевірені. Пакети не перебудовувалися.

## Невідповідності документації, усунені аудитом

Старий PLAN одночасно містив старі етапи, записи релізів і новий план: багатосторінковість була і майбутньою, і вже готовою; 0.17 описувалася як завершений електричний цикл; panel layout був одночасно post-MVP і наступним етапом. SYMBOL-LIBRARY змішував бажані PinId/version/licensing поля з поточним SymbolDefinition. «Редагований штамп» означав поля тексту, а не редактор стандартів. Тепер історія відокремлена, status matrix має пріоритет над старими release claims, одна DoD визначає 1.0. Версії 0.18–0.24 — майбутні результати, не випуски, підтверджені Git.
