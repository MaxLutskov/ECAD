# ECAD — єдиний план розвитку

Оновлено 2026-09-11. Application **0.18**; наступний етап — **0.19**. Це єдиний актуальний roadmap. [Історія](docs/CHANGELOG.md), [аудит](docs/AUDIT.md), [архітектура](docs/ARCHITECTURE.md), [UI/UX](docs/UI-UX.md) доповнюють його без паралельних списків релізів.

## 1. Vision / ціль продукту

Кросплатформний desktop ECAD для створення, перевірки й випуску електричних схем та базового 2D компонування щита. Windows і Ubuntu — основні платформи; початковий тестовий орієнтир Ubuntu 24.04 LTS, точну версію користувача ще не встановлено. Геометрія поєднується з моделлю пристроїв, контактів, кіл і фізичних виконань. PDF користувача — джерела сценаріїв, не завдання імпорту старих форматів.

## 2. Основні принципи

- Зберігати довільне й числове малювання та редагування в мм через спільні параметри. Точні значення не округляти до сітки; preview не змінює документ.
- Одна завершена дія — одна транзакція Undo. Графічна група, символ, функція пристрою і коло — різні поняття.
- Єдиний інструмент шляху має явний режим провідника/графічної лінії. Довільні кути та один перемикач кроку кута зберігаються. Перетин без вузла не створює з'єднання.
- Каталоги довільні: не лише IEC/ANSI/custom і не лише 1P/2P/3P. Конфігурації, виробники, номінали та фізичні виконання — дані. NO/NC не перекладати.
- Цілісність поточних файлів, ID і користувацькі дані мають пріоритет. Сумісність зі старими версіями зараз не потрібна.
- Incremental refactoring замість rewrite; UI викликає application commands. Assemblies створюються за межами відповідальності, не для кожної функції.
- До 1.0 — послідовні 0.18, 0.19…; номер означає прийнятий результат. App version, document schema та library schema незалежні.

## 3. Поточна архітектура верхнього рівня

`ECAD.Desktop` (Avalonia 12.1.2, UI/render/input/platform) → `ECAD.Core` (domain/geometry/session/persistence). `ECAD.Checks` → Desktop/Core, headless console runner. Усі — .NET 10. Application/Infrastructure ще не окремі проєкти. Core не залежить від Avalonia, але відповідальності змішані. Цільові межі та перенесення — в [ARCHITECTURE](docs/ARCHITECTURE.md).

## 4. Поточний стан

0.18 завершує стабілізацію прототипу перед оновленням UI. Геометрія, числові параметри, розміри, вибір/групи, символи, довільні провідники, каталоги та багатосторінкові документи працюють. Виправлено зміни кіл, посилання каталогів, history/dirty state, перевірки файлів і пакування. Докази — [приймання 0.18](docs/RELEASE-0.18.md).

Application 0.18; `.ecad` schema 13 з канонічними Pages; `.ecadlib` schema 1. Моделі пристроїв, клем і кабелів залишаються базовими. Міжсторінкові посилання графічні, штамп фіксований; компонування щита, PDF/друк/BOM, recovery та шари попереду.

## 5. Залишковий технічний борг

- 0.19: розділити UI, interaction і renderer; command/panel registries, read-only view models, події selection окремо від документа. Наявна межа application — EditorSession і чисті правила Core/Application; повний UI facade належить створити.
- 0.20: PinId, повний електричний граф, редактори функцій/клем/жил, рухомі номери провідників. Ownership функцій уже перевіряється.
- Історія має приватні серіалізовані snapshots; публічні domain arrays поки змінювані. Редагування продукту проходить через session. Delta undo — за результатами подальшого профілювання.
- Split призначеного кола потребує зняття призначень і повторного вибору гілки. Невикористані кола очищуються окремою командою; нерозміщені пристрої/функції автоматично не видаляються.
- Старі формати не є вимогою. Наявний loader/fixtures залишено без розширення гарантій сумісності.

## 6. Поточний етап: перехід до 0.19

Спочатку створити command registry з чинними діями та CanExecute, потім перебудувати shell і панелі, перенести inspector, відділити canvas rendering від interaction та виконати UI-приймання. Зберегти наявні geometry/save/undo сценарії. Версію 0.19 встановлюємо після виконання критеріїв нижче.

## 7. Єдиний roadmap

0.18 — підготовлений фундамент; наступні версії означають цільові етапи, а не вже випущені можливості.

### 0.19 — UI/UX Architecture & Redesign

- **Goal:** масштабований workspace для щоденної інженерної роботи.
- **Scope:** [UI-UX специфікація](docs/UI-UX.md): shell/docking/resizing, меню/toolbar/toolbox, command palette, inspector, project/page/library/electrical panels, context/status/notifications, keyboard, selection/snap feedback, numeric editors, icons/themes/localization/accessibility/HiDPI.
- **Architecture impact:** command/panel registries, ViewModels, reusable controls/tokens; renderer окремо від interaction; domain edits через facade. Контракти майбутніх панелей.
- **User-visible result:** центральне полотно, настроювані панелі, пошук команд замість додавання рядів кнопок.
- **Acceptance criteria:** наявні дії доступні через один command ID/CanExecute; L/C/R/D/P/A не заважають текстовим полям; multi-selection/mixed values і numeric input не гублять focus; layout save/reset працює; ERC переходить до об'єкта; ручні Windows/Ubuntu сценарії при 100/150/200% і вузькому вікні без обрізаних критичних полів; geometry/undo/save regressions проходять.
- **Dependencies:** 0.18.
- **Out of scope:** сама модель шарів, panel layout і повні електричні редактори наступного етапу; plugin SDK.

### 0.20 — Завершений електричний робочий цикл

- **Goal:** перейти від збереження сутностей до редагування й перевірки реальної схеми.
- **Scope:** пристрої/функції/стабільні PinId, прив'язка подань; клеми/рівні/мости; кабелі/жили/контактні кінці/екрани; правила номерів і рухомі анотації; електричні міжсторінкові зв'язки/адреси; навігація/ERC; завершення оновлення бібліотек і редактора символів. Базові PLC I/O — через конфігурації/функції.
- **Architecture impact:** Device→Function→Pin identity, project graph, annotations, library contact mapping, extensible ERC, міграція індексів контактів.
- **User-visible result:** котушка/контакти, клеми, жили та міжсторінкові кола редагуються у workspace; помилка веде до причини.
- **Acceptance criteria:** контакт не використовується двічі мовчки; міжсторінковий перехід впливає на connectivity; жила перевіряє обидва контакти/коло; spare/PE/shield і мости мають позитивні/негативні ERC cases; оновлення бібліотеки показує mapping; навчальна схема має 0 неочікуваних ERC, окремий приклад навмисних помилок та save/open/undo checks.
- **Dependencies:** 0.18, 0.19.
- **Out of scope:** автоматична трасировка, електротехнічні розрахунки, сертифіковані каталоги, PLC генератор.

### 0.21 — 2D компонування щита

- **Goal:** використати фізичні виконання у монтажному кресленні.
- **Scope:** workspace, корпус/панель/DIN-рейки/канали, вставка виконань, розміри/зазори, розміщені/нерозміщені пристрої.
- **Architecture impact:** panel model/placement commands, посилання на спільний ProjectDevice, renderer adapter.
- **User-visible result:** схема і фізичне розміщення мають спільний склад пристроїв.
- **Acceptance criteria:** кілька подань не подвоюють склад; заміна виконання перевіряє габарити; collisions/межі підсвічені; мм зберігаються після open/undo; приклад зі схемою та щитом.
- **Dependencies:** 0.20, shell 0.19.
- **Out of scope:** 3D, тепловий розрахунок, CNC, автоматичне компонування.

### 0.22 — Оформлення та випуск

- **Goal:** отримати комплект креслень і звітів для передачі.
- **Scope:** редактор рамок/штампів/шаблонів під узгоджені стандарти, поля/ревізії/зони; BOM, журнали клем/кабелів/жил; PDF/preview/друк; library snapshots, autosave/recovery/backup.
- **Architecture impact:** templates, report read models, document render/export поза UI, platform printing adapters, recovery service.
- **User-visible result:** схема, компоновка й відомості виходять узгодженим комплектом.
- **Acceptance criteria:** два редаговані шаблони перевірені за узгодженими зразками; PDF з кирилицею й правильним масштабом; BOM рахує пристрої, не символи; журнали збігаються з графом; preview відповідає PDF; друк Windows/Ubuntu перевірено; recovery не перезаписує збережений файл без дії користувача.
- **Dependencies:** 0.20, 0.21.
- **Out of scope:** всі світові стандарти, legacy import, ERP.

### 0.23 — Шари

- **Goal:** організація видимості й оформлення після основних ECAD сценаріїв.
- **Scope:** довільні шари, current/visibility/lock/print, порядок, колір/тип/товщина ByLayer та override, multi-selection assignment.
- **Architecture impact:** LayerId/model, shared style resolution canvas/print, selection policy, panel registry.
- **User-visible result:** керування графікою через панель шарів.
- **Acceptance criteria:** поточні об’єкти отримують default layer без зміни вигляду; locked не редагується, hidden не вибирається, non-print не потрапляє у PDF; приховування не розриває граф; save/open/undo зберігають семантику.
- **Dependencies:** 0.22. Остання функціональна стадія перед кваліфікацією випуску, згідно з пріоритетом користувача.
- **Out of scope:** розширені AutoCAD layer states/filters, DWG.

### 0.24 — Пілот і кваліфікація 1.0

- **Goal:** довести стабільність наскрізного сценарію.
- **Scope:** узгоджені фрагменти користувацьких схем, великі проєкти, performance budgets, Windows/Ubuntu matrix, пакування/оновлення, help і regressions.
- **Architecture impact:** профілювання й локальні оптимізації за доказами; release checks на відтворюваному stable SDK.
- **User-visible result:** перевірена збірка, приклади та інструкції запуску/оновлення/відновлення.
- **Acceptance criteria:** виконано DoD нижче; pan/zoom/edit/save/пам'ять на зафіксованому наборі схем і машині вкладаються у погоджені до пілота budgets; немає блокерів даних/основних сценаріїв; повторне встановлення не губить дані.
- **Dependencies:** 0.23 та всі попередні критерії.
- **Out of scope:** нові великі функції; 1.0 не видається лише через завершення нумерації.

## 8. Definition of Done для 1.0

1. Повний цикл: геометрія/пристрої → кола на кількох аркушах → клеми/кабелі → щит → ERC → PDF/звіти → save/open без втрат.
2. Acceptance criteria 0.18–0.24 закриті доказами; P1 і дефекти основних сценаріїв усунені. Шари включені, web/mobile — ні.
3. Перевірки поточного формату, undo, негативні ERC, recovery, приклади й UI regressions проходять CI; checks не видалені без еквівалента.
4. Реальні Windows та узгоджений Ubuntu перевірені, включно HiDPI/keyboard/print/packages; stable SDK, відтворювана збірка, performance результати.
5. Приклади мають очікувані результати ERC; користувач прийняв пілотний комплект. Draft/перевірено та джерела бібліотечної графіки явно вказані.
6. Документація/формати/help відповідають binary; Libraries/Projects захищені при оновленні. 1.0 означає цю DoD, не всі можливості великих ECAD систем.

## 9. Post-1.0 напрямки

Макроси/генерація повторюваних схем, розширена PLC I/O automation, інтеграції/звіти, контрольований plugin SDK, каталоги, 3D та додаткові engineering analyses за окремими вимогами. Web/mobile — спочатку дослідження сценаріїв і application contracts. Це не другий versioned roadmap.
