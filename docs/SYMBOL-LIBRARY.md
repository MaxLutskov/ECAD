# Бібліотеки та символи

Поточний стан: application 0.18. Це опис контрактів і вимог, не roadmap. Черговість завершення — [PLAN](../PLAN.md); обмеження — [AUDIT](AUDIT.md).

## Реалізований каталог

ComponentCatalog і LibraryEditorWindow підтримують довільні бібліотеки, типи з конфігураційними полями, сімейства/серії, варіанти та фізичні виконання. Поля можуть бути обов'язковими/необов'язковими, вільними або з переліком значень. 1P/2P/3P — лише приклади. Номінал, виробник, артикул, параметри, контакти, габарити, монтаж і 2D-контури — дані каталогу. Фізичні виконання ще не можна розмістити у workspace щита.

Є пошук, CRUD, копіювання з новими ID, імпорт/експорт `.ecadlib`. Файл — JSON envelope schema **1**; ComponentLibrary.Version — окрема ревізія вмісту. Каталоги зберігаються в документі. Перевірка охоплює всі сторінки й ProjectDevice, включно нерозміщеними пристроями; зміни фізичних виконань узгоджуються атомарно. Повний mapping контактів заплановано на 0.20.

Дві [демонстраційні бібліотеки](../examples/libraries) показують конфігурації, контакти та фізичні виконання; артикули DEMO не є перевіреними даними виробника.

## Реалізоване графічне визначення

У поточній стабілізації 0.18 перевірку видалення/оновлення каталогу поширено на всі аркуші й ProjectDevice. Заміна видаленого фізичного виконання узгоджує всі посилання однією транзакцією; несумісна зміна символу використаного варіанта блокується. Це усуває описане вище обмеження baseline 0.17, але повний редактор зіставлення контактів ще запланований.

SymbolDefinition має лише Key, Name, Prefix, PointMm[] Pins та optional SymbolStroke[] Strokes. Вбудовано 9 IEC і 3 ANSI-чернетки; custom symbol створюється з вибраної геометрії та вузлів. Позначення екземпляра — окремий рухомий текст. NO/NC залишаються технічними назвами.

Контакт зараз адресований ElementId+PinIndex, а не стабільним PinId. Немає versioned SymbolDefinition, мовних варіантів назв, electrical pin types, verified standard metadata або повного редактора pin mapping. Вбудована графіка визначена кодом за Key; вбудовані символи не мають незалежного замороженого snapshot версії графіки. Збереження custom definitions не гарантує незмінності всіх built-in symbols при оновленні програми.

## Цільові контракти, ще не реалізовані

Стабільні SymbolId/version та PinId з номером, функцією, напрямком й електричним типом; поля назв/параметрів і правила орієнтації; необов'язкові standard/profile/source/license/review metadata; project snapshots використаної графіки. Оновлення бібліотеки — явна операція з mapping контактів, preview та перевіркою з'єднань на всіх сторінках. Пристрій, функція, символ і фізичне виконання залишаються різними сутностями.

Відповідність конкретній редакції IEC/ANSI не підтверджена. Початкові symbols залишаються draft до перевірки. Для майбутніх зовнішніх наборів фіксуємо джерело й умови поширення, для параметрів виробника — точну модифікацію та документацію. Це вимоги, а не опис уже реалізованої standards library.
